05 / PROGRAMMING CONCEPTS

Object-oriented programming (OOP) • OOP is a way of organizing programs around objects that combine data and behavior. • Classes can describe the shared structure of related objects, while individual instances hold their own state. • Methods are functions associated with an object or class. • Encapsulation means keeping related data and operations together and controlling how that data is changed. • Inheritance and composition are design tools; they should be used when they make the model clearer. • An object-oriented design is not automatically better—simple functions may be enough for simple tasks. 16

06 / APIS & ASYNC

Asynchronous JavaScript • Some operations take time, such as downloading data or waiting for a response from a server. • Asynchronous programming allows the application to continue handling other work while waiting. • Promises represent the eventual success or failure of an asynchronous operation. • async and await provide syntax that makes promise-based code easier to read. • Applications should handle failures, such as network errors or unexpected responses. • Loading indicators and useful error messages make the experience clearer for users. 07 / TESTING

A practical testing workflow • Identify the behavior you want to verify. • Write a test that describes the expected result. • Run the test and inspect failures instead of ignoring them. • Fix the code or the test expectation based on the intended behavior. • Run the full test set after important changes. • Keep tests focused, readable, and connected to actual requirements. Testing is not only about finding bugs; it also documents how a piece of code is supposed to behave. 23

08 / COMPUTER SCIENCE

Recursion • Recursion occurs when a function solves a problem by calling itself on a smaller version of the problem. • A recursive solution needs a base case that stops the repeated calls. • Each recursive step should move closer to the base case. • Recursion can be natural for tree structures and problems that break into similar subproblems. • It can also use more call-stack memory than an iterative approach, so it is important to understand the trade- offs. Think of it as A smaller problem, then a smaller one, until a simple stopping case is reached. 24

Data structures: choosing how to store information • An array stores an ordered collection and is useful when items need positions or iteration. • A linked list connects nodes, each holding data and a reference to another node. • A hash map stores key-value pairs and is useful for looking up information by key. • A binary search tree organizes values by comparisons and can support efficient search when appropriately structured. • The best structure depends on what the application needs to do frequently: search, insert, delete, or traverse. 26

11 / PRACTICAL ADVICE

Common challenges and how to handle them • Too much information at once: take notes and focus on understanding one concept at a time. • Code copied without understanding: rewrite the example in your own words and explain each line. • Debugging feels confusing: reproduce the problem, read the error, and inspect values step by step. • Projects feel too large: break them into small features and complete one at a time. • Code becomes messy: use clear names, small functions, modules, and consistent formatting. • Progress feels slow: measure progress by what you can build and explain, not by speed alone. 30
